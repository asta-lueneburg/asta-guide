# Link Text & Contrast

Two things are in your hands with every publication and determine whether a page works
for everyone: **what your links say** and **which colors you use**.

## Link text

A link tells visitors where it leads. People using screen readers often jump from link to
link and hear only the link labels—a list of "click here", "more", and "link" is useless
in that situation.

| Poor | Better |
|---|---|
| Click here | Apply for Semesterticket |
| More | All counselling services |
| Read more | Refund deadlines in detail |
| www.fzs.de | Freier Zusammenschluss von Student*innenschaften (fzs) |
| Go to form | Application for committee certificate |

Rules:

- Link text describes the **destination**, not the action "click".
- Multiple links on the same page with the same text should lead to the same destination.
- A link should make sense even without the surrounding sentence.
- Filenames and bare URLs are not good link text—unless the URL itself *is* the
  information.

## Contrast

The theme ensures that text and background maintain sufficient contrast in both light and
dark modes. For that reason, the custom color picker, default WordPress palettes and
gradients, custom font sizes, and drop caps are locked in the editor via `theme.json`.
**Even so, you can still break contrast** if you paste formatting from Word/HTML or
combine unsuitable colors.

Therefore:

- Use only the visible AStA palette for text and backgrounds: `primary`, `secondary`,
  `accent`, `base`, `base-alt`, `contrast`, `contrast-alt`, `surface`, `link`.
- Never paste hex values or inline styles for text colors (use "Paste as plain text").
- Never use color as the sole way to convey meaning ("the red entries are important")—pair
  color with text or a symbol.
- Use bold instead of color when you want to emphasize something.

## Checking before publishing

Before publishing:

1. View the page in **dark mode** (toggle in the header).
2. Scan the links: would the page still make sense if only the link texts were read aloud?
3. Check images—see [Image Descriptions (Alt Text)](./bilder-alt-texte.mdx).

## If you spot an accessibility barrier

The website has an
[Accessibility Statement](https://asta-lueneburg.de/erklaerung-zur-barrierefreiheit/).
It describes the current status, known limitations, and how to report issues.

Report barriers there or to the webmaster team (webmaster@asta-lueneburg.de)—include the
page URL and a brief description of what does not work.
